Languages

Go

Check P specs against the events your code emits during go test.

Application code calls snappeaemit.Emit("eReserved", ...) where a change becomes visible. A test records those events and, when it ends, checks them against your P specs. You need only the specs (event declarations and spec machines), not a full P model.

It sees only the orderings your tests produce: it checks the implementation against the design, it does not explore other interleavings. For how this fits with model checking, see the overview.

Install

Go 1.22 or later. The module has two packages, both standard library only:

  • go/snappeaemit: Emit from application code, in tests, in processes tests start, and to production logs. This is all production code imports.
  • go/snappeatest: record and check events from tests.

snappeatest runs the snappea checker. It uses SNAPPEA_BIN, else snappea on PATH, else downloads the release binary for the module's version once into the user cache and verifies it against checksums in the module. Offline, or with SNAPPEA_DOWNLOAD=0, install it yourself: cargo install snappea or pip install pysnappea.

Test setup

A recording per test

Go has no global per-test hook, so each test opts in by calling snappeatest.Start. Put it in your existing fixture, next to the shared Config:

  • Start checks in a t.Cleanup. Register cleanups that stop workers after Start, so they run first. A test that already failed is not checked.
  • Each test, subtest and fuzz callback needs its own recording. Emitting after the check fails it.
  • snappeatest.New plus r.Check(t) checks where you call it; r.Verify(ctx) returns (Result, error) instead.
  • SNAPPEA_MODE=off makes recordings inert.

Parallel tests

The global snappeaemit.Emit cannot tell parallel tests apart: with several recordings active, it fails them all with a config error. For t.Parallel() tests, inject the recording's r.Emit into the application, or pass a context: snappeaemit.EmitCtx(ctx, ...) with ctx := r.Context(context.Background()).

Fuzzing

Call Start inside the f.Fuzz callback with its t, so each input gets a fresh recording.

Emitting events

  • Payload: a struct or map whose JSON names match the P named tuple, a single value, a slice for a tuple, or nil. It is encoded at once.
  • Key splits events into independent streams, such as one per product. Each stream gets its own instance of every spec.
  • Emit after the change commits, or specs see states that never existed.
  • The call site is recorded for failure reports.

In production

Emit never panics or blocks: a line that cannot be encoded or written, or that finds 4096 lines already queued, is dropped and counted by snappeaemit.Dropped(). Flush(timeout) waits for the queue; SetSink(nil) turns it off. In a process a test started, SetSink does nothing: events go to the test.

Other processes

Start a child with r.Env(), the environment plus SNAPPEA_EVENTS_DIR. If it uses snappeaemit, its events join the check. Wait for it before the check.

  • r.EventsDir() is the folder, for anything that writes the event lines itself.
  • r.AddEventsDir(path) adds a folder the recording did not create, such as a container volume.
  • r.AddLog(path, parse) adds a log; parse(line) (snappeatest.Event, bool) returns an event with Time set, or false to skip the line. nil reads JSON lines as they are.

Failures

A failure shows the spec's assert message, the events of the key that broke it with where each was emitted, the assert in the P file, and the folder that keeps the events and the checker's output. Check reports it with t.Errorf; Verify returns it:

*SpecViolation has Spec, Key, Message, Location (the P assert), Events (each with Event, Payload, Src), Liveness, Others and ArtifactsDir. Anything else is a *snappeatest.SetupError whose Kind is:

Settings

Go has no config file: settings are snappeatest.Config fields, with paths relative to WorkDir (default: the package folder). Environment variables override fields, except SNAPPEA_BIN, which Binary overrides. Strict is a *bool: use snappeatest.Bool(false). AllowUnobserved and ArtifactRoot are deprecated aliases for Strict: snappeatest.Bool(false) and Artifacts.

Suite coverage

Set Config.Coverage (or SNAPPEA_COVERAGE) and add func TestMain(m *testing.M) { snappeatest.Main(m) }. Main merges the P spec handlers, statements and branches every check reached into the file once, after the tests, and prints the summary. Without it, each check merges as it completes. The file is merged under a lock, so go test ./... packages can share it; delete a stale file before a run.
