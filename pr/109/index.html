The P language, in Rust

Fast formal models that also check your code

Snap Pea is a Rust implementation of P: a parser, type checker and model checker in one binary, with no compile step. It's built for speed, and for checking your application's real events against the same specs that checked its design.

A fast edit-check loop

Snap Pea interprets models directly instead of compiling them, and runs schedules in parallel, so short checks finish almost instantly. That makes it easy to check a model on every edit, in CI and inside application test suites.

What is P?

P is a language for modeling distributed systems as communicating state machines, and for checking those models against specs. It catches the design bugs that hide in rare orderings of messages, failures and retries, before they reach code.

It works at scale: P is used in industry to check the designs of large production systems, and its tutorials and case studies show how to model everything from two-phase commit to Paxos and Raft.

Snap Pea aims to make P easier to adopt in more projects. It keeps P's language and results, and is tested against P's own test suites and tutorials.

Install

The checker, from crates.io or PyPI:

$ cargo install snappea   # snappea and snappea-compat, with a Rust toolchain
$ pip install pysnappea     # prebuilt snappea, plus the Python helper
$ snappea check            # check every test case in the .pproj

Each GitHub release also has prebuilt snappea binaries for Linux, macOS and Windows. The application helpers are one snappea package per language:

$ pip install pysnappea                       # Python
$ cargo add --dev snappea                   # Rust
$ go get github.com/crowecawcaw/snappea     # Go

Java: io.github.crowecawcaw:snappea on Maven Central, plus a natives jar with the checker (Maven and Gradle snippets). Each language has a guide: Python, Rust, Go, Java.
