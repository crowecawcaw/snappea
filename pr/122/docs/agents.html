Work with your agent

Model a feature with your agent

Use a model to improve the design, then carry its rules and counterexamples into implementation tests.

Prerequisites: an installed Snap Pea CLI, an application repository, and a feature involving shared state, concurrency, retries or recovery. For an introduction to P, start with your first model.

Give the agent the contract

Describe what must remain true, the storage primitives that are actually atomic, and the failures you expect. Ask the agent to record assumptions and model bounds alongside the design. A useful starting instruction is:

The guide ships with the binary, so the agent can read it without browsing documentation. For a complete model-to-application example, ask it to readsnappea guide example reservation: an atomic reservation versus a stale read/write, with Python tests.

Review the model before implementation

Check that separate operations can interleave where the real system allows them to. A model that treats a read and a later write as one atomic operation assumes away the lost-update bug. Review specs against the contract independently of the implementation algorithm.

Use the reported replay command to inspect a failure. Fix the design when the trace exposes a real bug; fix the model when its assumptions are wrong. Keep the scenario that exposed it.

Coverage identifies behavior the workload did not exercise. Lints catch common weak models. Mutation testing asks whether checks reject changed behavior. Investigate findings rather than removing the checks to obtain a pass.

Connect the implementation to the spec

Ask the agent to implement the reviewed design and record actual operation arguments and results. Use the helpers for Python, Rust, Go or Java to check those events against the model's specs.

Force the important interleavings in implementation tests: for example, ensure two calls read the same value before either writes. Run the real application calls; do not replace them with invented event lists. Keep each model counterexample as a regression test where practical.

The inventory model and application examples share a stock-reservation spec across languages.

Keep the loop running in CI

Add snappea check and your ordinary application tests to CI. Start with automatic scheduling, then choose a time budget appropriate to the model. See GitHub Actions and the CLI reference.

Review search completion, model bounds, quality findings and instrumentation alongside a passing status. The model and observed events can both omit requirements. Update the design, model and tests together as the feature changes.

For how we measure agent outcomes, see the minimal-prompt eval.
