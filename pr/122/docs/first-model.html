Your first model

Find a lost update, inspect its trace, and change the design.

No installation or P experience is needed. You will use the browser Playground.

Run the broken design

Open the lost-update model. Press Check to run its test. Two clients each increment a counter. The assertion expects 2, but an execution can leave 1. Read the failing assertion and inspect the saved trace before changing the code.

Read the model

Each machine is a state machine with an inbox. send puts an event in another machine's inbox, and the checker decides when it's delivered. Here the Counter serves reads and writes, and each Client reads, then writes back the value plus one:

The test machine, Main, starts the Counter and two Clients. Once both Clients are done, it asserts that the counter reached 2:

If you have installed the CLI and saved the Playground file as LostUpdate.p, the equivalent check looks like this (timings and schedule counts vary):

The trace shows exactly how the update was lost:

counter0
A read–
B read–
final–

1/10 Main creates the Counter and two Clients. The counter starts at 0.

The fix is a design change: replace the read and write with one Increment event that the Counter applies itself. For this small model, automatic exhaustive exploration can finish and find no bug. Read the result to confirm whether it completed.

Open this model in the Playground →

Check the fix

In the Playground, change the Counter to handle one increment event. Change each Client to send that event instead of reading and writing. Keep the final assertion: two completed increments must leave 2. Declare the new event and remove unused read/write declarations. Run the checker again.

Keep ValueRead and the Counter's ReadFinalValue handler: Main still uses them to verify the final value.

The fixed design should pass. Read the result to see whether exploration completed or reached its budget. A pass checks this bounded model, not every possible implementation.

You have changed the design, not just the test order. Next, use the agent workflow to carry a model's rules into application tests.
