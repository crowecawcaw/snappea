Languages

Rust

Check P specs against the events your code emits during its #[test]s.

Application code calls emit("eReserved", ...) where a change becomes visible. A test records those events and checks them against your P specs, in process: no separate binary. You need only the specs (event declarations and spec machines), not a full P model.

It sees only the orderings your tests produce: it checks the implementation against the design, it does not explore other interleavings. For how this fits with model checking, see the overview.

Install

One crate, snappea, with features. Production code needs only the emitter, which compiles no checker and depends only on serde and serde_json:

FeatureAdds
emitsnappea::emit: send events to tests, child-process folders or production logs
test (default)snappea::test: in-process checks in #[test]s. Implies emit
cli (default)The snappea and snappea-compat binaries. default-features = false, features = ["test"] skips them

Test setup

A checked fixture

model.check(|recording| ...) records while the closure runs, then checks and panics with the failure output. Cargo has no global per-test hook, so each test opts in by calling it; put it in your existing fixture factory.

  • Put setup and cleanup inside the closure, and join worker threads there. Nothing is checked in Drop.
  • A panic in the closure propagates unchanged, with no second check.
  • Never share a recording between tests: Cargo runs tests in parallel.
  • Compile the Model once (in a LazyLock) and share it; clones are cheap.
  • SNAPPEA_MODE=off runs the closures without checking.

Model::load() reads [package.metadata.snappea]. Model::from_files(paths) and Model::compile(&[(name, text)]) (for include_str!) set up explicitly. Builders override any setting: .specs([..]), .exclude([..]), .strict(..), .check_hot(..), .unknown_events(..), .coverage(path).

Emitting events

  • Payload: anything Serialize: json!, a #[derive(Serialize)] struct, a scalar, or () for none. Named tuples are objects; enums go by name.
  • Key: anything Display. It splits events into independent streams, such as one per product; each stream gets its own instance of every spec.
  • Time: emit_at takes a SystemTime, or i64 epoch nanoseconds for a logical clock. Each key's events are checked in time order.
  • Emit after the change commits, or specs see states that never existed.
  • The call site is recorded with #[track_caller] and shown in failure reports.

Three ways to connect application code to a recording:

  • The global snappea::emit::emit: a recording binds the thread that creates it. Bind threads the test spawns with let _guard = recording.sink().bind();. With several recordings open and an unbound thread, the emit fails them all, so bind or inject.
  • recording.sink(): a cloneable EventSink to inject, as in the explicit check above. Its emit returns an error after the check.
  • recording.emitter(): a snappea::emit::Emitter, for code that takes one and gets a production Emitter otherwise.

In production

Emitting never panics, returns an error, or blocks on I/O. Writers queue up to 16,384 lines and drop events when the queue is full or a write fails; snappea::emit::dropped() counts them. With no sink, emit costs a few atomic loads, but the payload is still built; code holding an Emitter can skip a costly one with is_on().

Other processes

A child process that calls snappea::emit::emit writes to recording.events_dir() through SNAPPEA_EVENTS_DIR; anything else can write the same JSON lines there. Stop or join children before the check. A failed check keeps the folder and names it.

Failures

A failure shows the spec's assert message, the events of the key that broke it (the last 20) with where each was emitted, and the assert in the P file. Model::check panics with it; check() returns CheckError::Violation(SpecViolation) or CheckError::Setup(SetupError). Assert on fields, not text:

SetupError.kind is one of:

KindCause
ErrorKind::ConfigBad options or config file, missing spec files, P compile errors, an unknown spec name
ErrorKind::ParserA payload that does not match its P declaration, or an unreadable event line
ErrorKind::Validationstrict: a selected spec saw no relevant event
ErrorKind::UnknownEventAn event name no P file declares
ErrorKind::OutOfOrderLive input out of order

Suite coverage

Set coverage (or SNAPPEA_COVERAGE) and every check merges the P spec handlers, statements and branches it reached into that file, under a lock, so parallel tests and test binaries share it. The summary prints when coverage changes (cargo test -- --nocapture shows it). Delete a stale file before a run.
