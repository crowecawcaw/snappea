# Website

The project site, built with Vite and React. The landing page and docs are rendered
to HTML at build time, including navigation, code highlighting and initial diagrams.
Their content is readable without JavaScript. Only interactive islands hydrate in
the browser; the playground remains a client application.

- `index.html`: the landing page (`src/site/home/`).
- `docs/*.html`: docs pages (`src/site/docs/`). Add a page by adding an HTML entry
  in `vite.config.ts`, its component in `src/site/render.tsx`, and a link in
  `src/site/docs/DocsLayout.tsx`.
- `docs/python.html`, `rust.html`, `go.html`, `java.html`: one page per language helper
  (`src/site/docs/languages/`), all with the outline in
  [language-support.md](../docs/language-support.md#docs-page). `languages/shared.tsx`
  holds the tables they share.
- `docs/api/python/`: the Python API reference, generated by pdoc in
  `.github/workflows/pages.yml`, so it exists only in the published site.
- `playground.html`: the P Playground (`src/App.tsx`), for editing and
  model-checking P models in the browser. It runs the `snappea-wasm` build of the
  toolchain in a Web Worker; nothing is sent to a server.
  Drop `.p` files, a folder or a `.zip` on the page (or use Open) to load a project.
  The URL tracks the project so links can be shared: `?demo=<id>&file=<path>` for an
  unedited demo, otherwise the files, open file and checker settings are deflated into
  `#s=...` (`src/share.ts`). Projects over 32k encoded characters are not put in the URL.
  Checks pass `--warn all`, so lint findings and coverage gaps show as warnings, unless
  Options > "Strict checks" is ticked (the CLI's defaults). The setting is in the link.

Docs pages follow Diátaxis and declare their type, personas and reader questions
in non-rendered meta tags in each HTML entry; see [AGENTS.md](../AGENTS.md#documentation).
The homepage reuses the shared-spec diagram and adds a mini Playground island
(`src/site/home/MiniPlayground.tsx`). It starts the real checker worker only on Run,
with a two-second exploration budget and mutation checks disabled. Users can edit
both P files and carry them into the full Playground with a share link.

The docs diagrams are React components driven by scripted data
(`src/site/docs/diagrams/`). `build/static-pages.ts` renders `src/site/render.tsx`
for both development requests and production HTML entries. Wrap interactive
components in `src/site/Island.tsx` and register their lazy loaders in the page
entry (`src/site/docs/main.tsx` or `src/site/home/main.tsx`). Keep initial renders
independent of browser APIs so HTML and hydration match; read media queries in effects.

```sh
cd web
npm ci
npm run dev      # builds the wasm module (needs the wasm32-unknown-unknown target), then starts Vite
npm run build    # production build in dist/
npm run test:html # verify published content is present in the HTML
```

- Demo models come straight from the repository (`tests/upstream/Tutorial`,
  `design/time/RetryBudget`, `web/demos`); see `src/demos.ts`.
- Projects are checked with `snappea check <every .p file> <test>`, so `.pproj` files are not used.
- `.github/workflows/pages.yml` publishes `main` to GitHub Pages and maintainer PRs to `pr/<number>/`.

The Model tab derives actors, assertions, and state diagrams from the Rust parser
via the Wasm-only `playground-model` request. This reads the current files;
comments and strings cannot create diagram nodes. Arrows represent explicit
`on ... goto` transitions and `goto` statements reached through state actions or
named statement calls (including conditional/loop/receive bodies). Conditions
still apply; this is a declaration diagram, not a reachability proof or a list of
enabled runtime choices. Foreign implementations are not expanded.

Checks request `--inspect-trace`: the first failing schedule is replayed with
source probes, fields, active-frame locals, and writes (including unchanged
values). Search itself uses the usual bytecode. Ordinary CLI and compatibility
traces retain their format unless this option is requested. Captures are bounded
at 10,000 snapshots and value previews at 500 characters; truncation is marked.

Trace > Walkthrough, Sequence, and States share a cursor. The walkthrough shows
captured values and pending messages reconstructed from sends/receives; the
variable history lets readers jump from writes to the surrounding messages.
Snapshots explicitly retain their capture positions. Editing source or selecting
another test marks the previous execution stale and pauses its source links.
Follow source scrolls the editor without taking its keyboard focus.

`npm run test:replay` checks inbox reconstruction and snapshot capture positions.
Rust tests in `snappea-wasm::model` check diagram extraction; interpreter tests
check that inspection preserves execution and records equal-value writes.
