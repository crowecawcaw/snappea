## Portable seeded probes and reference incompatibility

The grader first runs submitted tests against its private reference, and only runs seeded variants when that baseline passes (`a01/private/grade.py:161-185`). a02, b01 and c01 reject the reference and have **uninterpretable mutation evidence**, not zero kills. Their saved tests demand a ValueError on a mismatched-capacity Queue constructor, while `flow/private/reference_solution.py:5-9` only stores capacity on the object and never rejects mismatch. That is a concrete source explanation for incompatibility; grade JSON preserves reference_status/tests_rejected and test count, but not full baseline failure output, so no unrecorded traceback is claimed. The normal task domain assumes sharing instances use the same capacity; this extra mismatch expectation can make a useful submission-specific test nonportable without showing required-domain failure.

a01, b02 and c02 pass the reference baseline. Each rejects probes 01/02 and accepts probe 03. Calibration source (`a01/private/calibration.py:4-19`) defines 01 as LIFO, 02 as disabled put/take memo hits, and 03 as returning after compare_swap regardless of success. Thus each compatible suite distinguishes FIFO and memo faults but does not distinguish the seeded lost-CAS-retry fault in the recorded probe. This includes b02's threaded tests; without a forced collision, threads alone do not ensure the seeded fault manifests. These are three selected faults, not broad fault coverage. Incompatible suites are omitted from that mutation comparison, rather than counted as failures to kill.

## Descriptive comparison across two FIFO runs per condition

The none pair has one complete primary model and one incomplete primary model; both models omit selected QueueContract, while both produce actual captured CLI observation in transcripts (b02 saves the invocation, a01 does not). Both implementations pass the eight primary tests, but b02's monitor adds an unsupported zero-sentinel requirement. The old pair contains one real None-memo implementation failure and unfinished put-only CAS coverage (b01), and one passing atomic-queue abstraction that omits snapshots (c02); both have actual monitor-backed Python capture. The revised pair has no primary implementation failure, but diverges sharply in P: c01's monitor receives no events and CAS loss is abandoned, while a02 models full-record CAS retries and Store-order observations. Both read the same cas-retry README, neither reads/runs its executable source; neither retains completion/useful-success checks or generated request definitions. a02 additionally rejects a valid false-take placeholder and ignores snapshot-only wrong effects. These within-condition differences and the tiny sample do not support attributing outcomes to the condition. They identify specific mechanisms transferred or omitted and concrete artifacts a future revision can address.
