## Evidence limits and descriptive comparison

Reading the revised examples is documented for both revised runs, including actual P files, rather than merely their README. Both implement concrete read/recompute/CAS loops; those also occur in old/no-skill solutions. c02 demonstrably adds a replay client in response to coverage, while b01 uses the explicit exploratory coverage opt-out after narrowing its monitor. Both revised implementations omit the already-published no-reapplication distinction even though their example material emphasizes immediate state checks after retries; this is a descriptive omission in these two sources, not evidence of a causal effect or absence of understanding.

The old runs read actual Revalidated.p, model before code, and use separate monitors; neither submitted model includes concrete immutable-record preparation/recovery. a01 additionally executes useful inline implementation checks but overstates the isolated post-root crash boundary. b02 runs useful checks against an earlier version, then its last unvalidated layout edit fails to finish. No-skill runs implement first; c01 suppresses the independent-oracle lint and a02 spends many calls resolving syntax before adding reverse-order coverage. These observations describe tool interaction, not private reasoning or broad model tendencies.

Across all six, no actual implementation history is checked by a P monitor, no oracle positive/negative fixtures are independently run, no mutation campaign executes, and no new executable implementation-test file survives in the submission. Final bounded model passes establish only the specific submitted abstractions; source audit, public tests, original primary grade, inline probes and supplemental wide checks each provide different and limited evidence. With n=2 per task/condition, no effect-size, statistical or general causal claim is warranted.
