# Migration contract and calibration notes

The public contract uses initial rows `a` and `b` as the only rows that require the historical backfill. Any key created or changed after service start is dual-written atomically, including deletes as tombstones. Therefore a successful snapshot apply needs to fill or refresh only those initial rows; all live-created rows already have current shadow revisions. The fixed Python service accepts any string key, and observation histories cover new keys such as `c` and `d`.

There is one active staged snapshot. A new `prepare` supersedes the prior token. `apply` is one atomic public operation in this evaluation, merging the staged rows if their revisions are newer; writes and deletes may run after preparation and before application. Writes and deletes each atomically update the logical table, allocate a strictly greater positive revision, and dual-write the encoded row or tombstone. Cutover is an atomic switch after `ready` reports full logical/shadow equality. Repeated cutover while ready succeeds. Post-cutover writes and deletes remain visible through the new read path.

The Python checker monitor tracks the fixed initial rows explicitly because calibration initially hit a checker panic with a machine-field foreach iterator. Root isolation later showed handler-local iterators work; general map iteration is supported. It still accepts arbitrary new keys in live events and validates each observed shadow row through `eNewRow`. The monitor's expected shadow state for any live-created key follows from the dual-write contract. The ignored artifact at `phases/runs/calibration-migration/map-iteration-panic/` preserves the observer input and raw panic output for this checker finding.

The public model reference separates the `BackfillWorker` and `LiveWriter`, but its current check has incomplete coverage: the schedule reaches prepare/apply with live changes but does not reach all cutover, invalid-token, and tombstone-snapshot branches. Treat its successful explored schedules as partial model evidence; the saved Python suite and independent event-history calibration cover those public obligations. This is an eval fixture limitation, not a claim that the P search proves the full contract.
