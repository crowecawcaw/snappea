# Independent source audit

- **Model v2-01 uses a genuine read/decide/CAS loop.** `Store` returns a record snapshot at `iReadRecord` and applies all fields together only when the version matches at `iCAS` (`phase-model-v2-01/submission/model.p:31-47,50-73`). Clients derive a candidate from the snapshot and submit the expected version (`phase-model-v2-01/submission/model.p:184-219`); on conflict they reread and retry the same operation (`phase-model-v2-01/submission/model.p:223-233`). Rejected conditional calls announce at the read that establishes rejection (`phase-model-v2-01/submission/model.p:31-42`), while successful mutations announce in the successful CAS handler (`phase-model-v2-01/submission/model.p:50-69`).
- **Model v2-02 also has a real record read/CAS/retry path.** `Storage` returns the current record (`phase-model-v2-02/submission/model.p:29-34`) and atomically copies a proposed record only if its version matches (`phase-model-v2-02/submission/model.p:35-53`). `Operation` computes from a snapshot (`phase-model-v2-02/submission/model.p:82-105`) and rereads after failed CAS (`phase-model-v2-02/submission/model.p:109-113`). Rejected acquire/write/release decisions still CAS a version-only update before announcing, which serializes them against intervening operations (`phase-model-v2-02/submission/model.p:84-105,35-53`).
- **The model monitors are independent of implementation state.** Both observe only the six public events declared in `events.p` (`phase-model-v2-01/submission/monitor.p:1`; `phase-model-v2-02/submission/monitor.p:1`) and keep their own clock, value, token history, and lease state. The first permits any strictly increasing token (`phase-model-v2-01/submission/monitor.p:21-35`); the second permits gaps by requiring `token >= nextToken` and advancing from the observed token (`phase-model-v2-02/submission/monitor.p:14-22`).
- **The v5 Python tests preserve test provenance.** Each frozen `test_lease.py` imports the supplied `Service`, wraps its public calls, records the results returned by those calls as events, then sends that history to `check_events` with only `events.p` and `lease_contract.p` (`phase-test-v5-01/submission/test_lease.py:3-6,15-59,61-70`; `phase-test-v5-02/submission/test_lease.py:4-6,25-69,14-23`). Neither test module replaces service behavior or edits supplied service/contract sources. The public task explicitly asks for wrapper-captured operations and forbids modifying supplied files (`phase-test-v5-01/public/TASK.md:3-5,17-27`; `phase-test-v5-02/public/TASK.md:3-5,17-27`).
- **The requested test distinctions are present.** Both suites separately falsify owner and token write guards and read immediately afterward to check stored-value preservation (`phase-test-v5-01/submission/test_lease.py:94-103`; `phase-test-v5-02/submission/test_lease.py:84-91`). Both exercise expiry with the old, otherwise-correct owner/token, isolating the time guard (`phase-test-v5-01/submission/test_lease.py:118-135`; `phase-test-v5-02/submission/test_lease.py:128-145`). Both acquire a successor and then reject a stale release from the prior lease while checking that the successor remains visible (`phase-test-v5-01/submission/test_lease.py:112-136`; `phase-test-v5-02/submission/test_lease.py:98-114`).
